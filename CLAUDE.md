# First Thought

## What this app is

First Thought is a morning wake-up app. Instead of waking to a harsh alarm and immediately checking the phone, the user wakes gently and moves straight into a short guided meditation, then chooses how they want to meet the day.

The morning sequence, once the alarm time arrives:

1. A gentle alarm sound plays.
2. The alarm fades out and a soft ambient soundtrack begins.
3. A guided meditation (10 to 15 minutes) plays over the ambient sound.
4. The meditation ends and the user starts their day.

The experience should need almost no interaction. Full product notes live in `docs/product.md`. Read that file before making product or design decisions.

## Emotional tone (this matters in every screen, string, and sound)

The app must feel **calm, warm, human, grounded, simple, and non-cheesy**. It should feel like a calm person sitting beside you, not an app cheering at you.

- No forced positivity, no generic motivational language, no excessive spirituality.
- Never tell the user how they should feel. Help them choose their own intention.
- Wrong: "Today is going to be AMAZING! You can achieve anything!"
- Right: "You don't need to figure everything out today. For now, just notice that you're here."
- Sounds should create space rather than announce "this is meditation." Think morning light, not spa music.
- UI is minimal and clean. Prefer empty space, a small amount of text, and quiet colors. No badges, confetti, streaks, or exclamation marks.

## Tech stack

- **Expo SDK 57** (React Native 0.86, React 19). Always check the exact versioned docs at https://docs.expo.dev/versions/v57.0.0/ before writing code, because Expo APIs change between SDK versions.
- **JavaScript only.** No TypeScript.
- **Tested on a real iPhone using Expo Go.** Everything must run inside Expo Go with no custom native code and no development build.
- **Do not add libraries unless clearly needed.** When a library is genuinely needed, prefer the official `expo-*` package for it, and confirm it works inside Expo Go before adding it. Explain why the library is needed before installing it.
- Current dependencies: `expo`, `expo-status-bar`, `expo-keep-awake`, `expo-audio`, `@react-native-community/datetimepicker`, `react`, `react-native`. Nothing else yet.
- `assets/audio` contains placeholder WAV files generated by `scripts/make-placeholder-audio.js`; they will be replaced later with real recordings using the same file names.

## Scope: version 0.1 only

Build **only** these five things for v0.1:

1. **Alarm time.** The user picks a time. The app remembers it.
2. **One meditation audio.** A single bundled audio file. No choice of meditations.
3. **One ambient soundtrack.** A single bundled audio file that plays under the meditation.
4. **A timer.** Drives the morning sequence (alarm, then ambient, then meditation) and shows time remaining during the meditation.
5. **A minimal UI.** A home screen showing the alarm time and the meditation, and a very quiet screen during the meditation.

Explicitly **out of scope** for v0.1. Do not build, stub, or leave placeholders for any of these:

- Multiple meditation themes
- Mood or intention selection ("How do you want to feel?")
- Multiple soundscapes
- A true system alarm (see below)
- AI-personalized meditations, mood history, sleep data, daily variation
- Accounts, settings screens, onboarding, analytics

If a task seems to need something from this list, stop and say so instead of building it.

## Key technical decision for v0.1: no true system alarm yet

iOS does not let an Expo Go app ring like the built-in Clock alarm. A real system alarm is planned for **v0.2 using iOS AlarmKit**, which requires a development build. That is not part of v0.1.

For v0.1 the app must work entirely inside Expo Go, and these two things must work:

**a) Foreground overnight mode.** If the user leaves the app open in the foreground overnight (screen on, app not backgrounded), then at the chosen alarm time the app plays the alarm sound, then the ambient sound, then the meditation, fully automatically with no taps. The app should keep the screen awake while waiting so the sequence is not interrupted.

**b) Local notification backup.** When the user sets the alarm, the app also schedules a local notification for that time. If the app was closed or backgrounded, tapping the notification opens the app and immediately starts the same morning sequence. The notification is a backup path, not the primary alarm.

Both paths must run the exact same sequence code so there is one morning flow, not two.

## Working rules

- **Keep files small and simple.** One clear purpose per file. Prefer a few short files over one large one. Plain functions and plain React components; no clever abstractions.
- **Build only what the prompt asks for.** Never add extra features, screens, options, or "while I'm here" improvements. If something else seems necessary, mention it and wait.
- **Explain changes in plain language after each task.** The project owner is new to VS Code and React Native. After every task, list which files were created or changed and what each change does, in everyday words. Avoid jargon, or explain it the first time it is used.
- **Stay inside Expo Go.** Before using any API, confirm it works in Expo Go on iOS. If it does not, say so and propose the closest thing that does.
- **Check the Expo SDK 57 docs first.** Do not rely on memory of older Expo APIs (for example, `expo-av` has been replaced by `expo-audio`). Verify against the versioned docs linked above.
- **Do not change tone to be "friendlier."** Every string shown to the user follows the emotional tone section above.
- **Do not commit or push unless asked.**
